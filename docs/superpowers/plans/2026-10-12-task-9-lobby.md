# Task 9 Lobby Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players can claim the single Tipster seat first-come, and the host can start the game once a Tipster and a Guesser exist.

**Architecture:** Pure rule functions in `session.ts` decide every command. A new `POST /sessions/{squid}/commands` route in the game API Lambda loads, applies and conditionally writes, retrying on version conflicts. The browser lobby derives what it shows from the latest snapshot through a pure `lobbyView`.

**Tech Stack:** TypeScript, Node 22.23 test runner via `tsx`, AWS Lambda + DynamoDB (`@aws-sdk/lib-dynamodb`), Amplify Gen 2 / CDK, Vite.

**Spec:** `docs/superpowers/specs/2026-10-12-task-9-lobby-design.md`

## Global Constraints

- One commit for all of Task 9 at the end (TASKS.md workflow), after `npm run check` and sandbox verification.
- `amplify/backend.ts` is the source of truth; redeploy `round-about-dev` (`AWS_PROFILE=chreisel`, Node v22.23.3) before testing against AWS.
- Never log tokens or session contents; only error names.
- Keep the UI sparse: no rules text, one line of players. Render user-supplied text (nicknames) only through `textContent`.
- Error messages verbatim: "Only the host can start the game.", "The game has already started.", "<nickname> is already the Tipster.", "Someone needs to be the Tipster first.", "At least one Guesser needs to join first.", "Not available yet."

## Review Focus

1. A malformed command body (missing `command`, wrong `protocolVersion`, long `commandId`) should answer 400 `INVALID_INPUT`, never 500. Pinned in Task 2.
2. A retried `START` or claim after success should answer 200, not an error. Pinned in Task 1.
3. A host who is also the Tipster, alone in the session, must not be able to start. Pinned in Task 1.
4. A command with a wrong or missing token should answer 401 and leave the session unchanged. Pinned in Task 4 (sandbox script).
5. The lobby must show the server's latest state after a failed command (for example the seat was just taken), not a stale button. Pinned in Task 3 (`lobbyView` on the error snapshot).

HTTP: `POST /sessions/{squid}/commands` → 200 `CallerSnapshot` or `ApiError` with `snapshot` (403 `FORBIDDEN`, 409 `INVALID_PHASE`, 409 `STALE_VERSION`, 400 `INVALID_INPUT`).

  - `apply dispatches and rejects later commands`: `applyCommand(s, host, {type:"CLAIM_TIPSTER"}).tipsterId === host`; `{type:"DRAW"}` throws "Not available yet.".
- [ ] **Step 2: Run** `node --import tsx --test amplify/functions/game-api/command.test.ts`. Expected: FAIL.

Catch `CommandError` → status 403 for `FORBIDDEN`, 400 for `INVALID_INPUT`, 409 otherwise, body `{code, message, snapshot: projectCaller(latest, participantId, Date.now())}`. In `backend.ts` add route `/sessions/{squid}/commands`, `POST`, integration id `CommandIntegration`.
